NDAOHODY — TESTER LES ÉTAPES 6 À 11 (PUBLIER, RECHERCHER, RÉSERVER, SUIVRE, COURSE, AVIS)
À faire dans l'ordre, dans Postman. Chaque requête utilise ce que la précédente a renvoyé.

[TOKEN CHAUFFEUR]  = Authorization -> Bearer Token -> accessToken du chauffeur (034 00 000 03)
[TOKEN PASSAGER 1] = accessToken du passager 1 (034 00 000 11)
[TOKEN PASSAGER 2] = accessToken du passager 2 (034 00 000 07)
Les GET : copier l'URL complète, Body = none. Les POST / PATCH : Body -> raw -> JSON.
Un accessToken dure 15 min : en cas de 401, refaire la connexion de ce compte.


==============================================================
 0. PRÉPARER
==============================================================

1. Remettre les données de démo à zéro :   npm run db:seed
2. Démarrer le back :                      npx nx serve back
   (la nouvelle migration s'applique toute seule ; les trajets de démo prévus dans le passé
    sont annulés automatiquement dans la première minute : c'est normal)

POST http://localhost:3000/api/v1/auth/otp
-> Code SMS pour le CHAUFFEUR (Rabe Andry, chauffeur validé, voiture 1357 TBD). Le code s'affiche dans le terminal.
{
  "telephone": "034 00 000 03"
}

POST http://localhost:3000/api/v1/auth/otp/verify
-> Connexion du chauffeur. Copier l'accessToken : c'est le TOKEN CHAUFFEUR.
{
  "telephone": "034 00 000 03",
  "code": "code reçu dans le terminal du back"
}

Refaire ces 2 requêtes avec 034 00 000 11 (TOKEN PASSAGER 1), puis avec 034 00 000 07 (TOKEN PASSAGER 2).

 ÉTAPE 7 — RECHERCHER                             [TOKEN PASSAGER 1]
==============================================================

Un chauffeur sans position depuis 2 minutes passe hors ligne et disparaît des recherches
(étape 9). Les trajets de démo n'envoient pas de position : ils n'apparaissent plus.
Juste avant de chercher, le chauffeur envoie donc sa position :

POST http://localhost:3000/api/v1/me/position                          [TOKEN CHAUFFEUR]
-> Le chauffeur est au départ de son TRAJET IMMÉDIAT (Andoharanofotsy) : il reste en ligne 2 minutes.
{
  "latitude": -18.9850,
  "longitude": 47.5330
}

POST http://localhost:3000/api/v1/trips/search
-> Tanjombato -> Analakely, maintenant (moins de 2 minutes après la position ci-dessus).
   Attendu : 200 avec le TRAJET IMMÉDIAT (Andry).
   Chaque résultat : arriveeDansMinutes, distanceMetres, prixParPlace, prixTotal, sans téléphone.
   Pour la suite, garder du résultat du TRAJET IMMÉDIAT : "priseEnCharge" et "depose".
{
  "depart": { "libelle": "Tanjombato", "latitude": -18.9600, "longitude": 47.5280 },
  "destination": { "libelle": "Analakely", "latitude": -18.9067, "longitude": 47.5253 },

  "quand": "maintenant"
}

POST http://localhost:3000/api/v1/trips/search
-> Le sens inverse, Analakely -> Tanjombato : ni le trajet n°1, ni le TRAJET IMMÉDIAT
   (le passager doit monter AVANT de descendre, dans le sens du chauffeur).
{
  "depart": { "libelle": "Analakely", "latitude": -18.9067, "longitude": 47.5253 },
  "destination": { "libelle": "Tanjombato", "latitude": -18.9600, "longitude": 47.5280 },
  "places": 1,
  "quand": "maintenant"
}

POST http://localhost:3000/api/v1/trips/search
-> Plus tard : le TRAJET PRÉVU passe à Ivato vers 8h00. Attendu : il apparaît, avec "heurePassage".
{
  "depart": { "libelle": "Ivato, aéroport", "latitude": -18.7969, "longitude": 47.4788 },
  "destination": { "libelle": "Analakely", "latitude": -18.9067, "longitude": 47.5253 },

==============================================================
 SI ÇA NE MARCHE PAS
==============================================================

401 -> le token de ce compte a expiré (15 min) : refaire sa connexion (partie 0).
400 "property ... should not exist" -> un champ en trop dans le body (ex. "chemin" sur /trips).
400 "Ta prise en charge et ta dépose doivent être sur le chemin du chauffeur"
    -> reprendre exactement "priseEnCharge" et "depose" du résultat de /trips/search.
409 "Tu as déjà une demande en cours sur ce trajet" -> ce passager a déjà une demande active ici.
500 -> envoyer l'erreur affichée dans le terminal du back (une requête SQL a pu échouer).
503 -> Mapbox ne répond pas (Internet, MAPBOX_ACCESS_TOKEN).
